# HTTP Methods

## Определения

### HTTP-методы

::: tip HTTP-методы

- **HTTP-методы** - последовательность из любых символов, кроме управляющих и разделителей, указывающая на основную операцию над ресурсом

:::

### CRUD

::: tip CRUD

- **CRUD** - акроним, обозначающий четыре базовые функции, используемые при работе с базами данных: Create (создание), Read (чтение), Update (модификация), Delete (удаление)
- В системах, реализующих доступ к базе данных через API в стиле REST, эти функции реализуются зачастую (но не обязательно) через HTTP-методы PUT, POST, GET, PATCH, DELETE

:::

### "Идемпотентный" и "Неидемпотентный" метод

::: tip Идемпотентный метод

- **Идемпотентный метод** - метод HTTP является идемпотентным, если повторный идентичный запрос, сделанный один или несколько раз подряд, имеет один и тот же эффект, не изменяющий состояние сервера
- Идемпотентный метод не должен иметь никаких побочных эффектов (side-effects), кроме сбора статистики или подобных операций
- Примеры: GET, PUT, DELETE, HEAD

---

- **Неидемпотентный метод** - противоположный идемпотентному
- Примеры: POST

:::

## HTTP-методы

- Payload включается в тело запроса

### <v-badge theme="blue">GET</v-badge>

| Свойство        | Значение                                                 |
| --------------- | -------------------------------------------------------- |
| **Кеширование** | ✅                                                       |
| **API**         | `/api/user` - получить информацию обо всех пользователях |
| **Назначение**  | Получить содержимое ресурса                              |

- К GET-запросу в теории можно добавить BODY, но для этого лучше использовать POST

::: details Варианты GET

- `/api/users` - получить информацию обо всех пользователях
- `/api/user/{user_id}` - получить информацию о пользователе с указанным ID
- `/api/users?status=active&sort=desc` - получить информацию обо всех пользователях с заданием дополнительных Query Parameters

:::

---

### <v-badge theme="green">POST</v-badge>

| Свойство        | Значение                                                                                                        |
| --------------- | --------------------------------------------------------------------------------------------------------------- |
| **Кеширование** | 🅾️                                                                                                              |
| **API**         | `/api/users` - добавить нового пользователя                                                                     |
| **Назначение**  | Создать новый ресурс и передать пользовательские данные в виде payload: <br> `{ id: 1, name: 'Jack', age: 23 }` |

- Метод предполагает, что по указанному URI будет производиться обработка передаваемого клиентом содержимого
- Если был создан ресурс, то серверу следует вернуть ответ 201 (Created) с указанием URI нового ресурса в заголовке Location

---

### <v-badge theme="orange">PUT</v-badge>

| Свойство        | Значение                                                                                                                                                            |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Кеширование** | 🅾️                                                                                                                                                                  |
| **API**         | `/api/user/{user_id}` - заменить ВСЮ информацию о пользователе с указанным ID                                                                                       |
| **Назначение**  | **Full Update**. <br> Обновить существующий ресурс (или создать новый, если его нет) и передать пользовательские данные в виде payload: `{ name: 'Jack', age: 23 }` |

- _Если не передать одно из полей - оно будет null_
- В PUT содержится новая версия ресурса целиком
- Метод предполагает, что загружаемое содержимое соответствует находящемуся по данному URI ресурсу
- Если по заданному URI не существует ресурса, то сервер создаёт его и возвращает статус 201 (Created)

---

### <v-badge theme="lime">PATCH</v-badge>

| Свойство        | Значение                                                                                                                                                   |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Кеширование** | 🅾️                                                                                                                                                         |
| **API**         | `/api/user/{user_id}` - обновить ЧАСТИЧНУЮ информацию о пользователе с указанным ID                                                                        |
| **Назначение**  | **Partial Update** (аналогичен PUT) <br> Обновить ФРАГМЕНТ существующего ресурса и передать пользовательские данные в виде payload:<br> `{ name: 'Tony' }` |

- Передавать можно только необходимые поля. Остальные поля останутся без изменения

---

### <v-badge theme="gray">HEAD</v-badge>

| Свойство        | Значение                                                                            |
| --------------- | ----------------------------------------------------------------------------------- |
| **Кеширование** | ✅                                                                                  |
| **API**         | -                                                                                   |
| **Назначение**  | Проверка наличия ресурса. Получение информации о ресурсе, не получая самого ресурса |

- Аналогичен GET, но в ответе сервера отсутствует тело
- Обычно применяется для извлечения метаданных, проверки наличия ресурса (валидация URL) и чтобы узнать, не изменился ли он с момента последнего обращения. Заголовки ответа могут кэшироваться. При несовпадении метаданных ресурса с соответствующей информацией в кэше - копия ресурса помечается как устаревшая

## Отличия

### GET vs POST

- _GET_ может кешироваться браузером. GET идемпотентный: сколько бы раз не запрашивали в Google некоторый запрос, Google вернет тот же результат
- _POST_ не кешируется браузером. POST не идемпотентный: он может вставлять в базу новую строку каждый раз

### POST vs PUT

- _POST_ предполагает, что по указанному URI будет производиться обработка передаваемого клиентом содержимого. POST не идемпотентный - отправка одних и тех же запросов POST несколько раз может привести к созданию нескольких ресурсов
- _PUT_ предполагает, что загружаемое содержимое соответствует находящемуся по данному URI ресурсу. PUT идемпотентный

### PUT vs PATCH

- _PUT_ - замена. Необходимо передавать полный список полей, в отсутствующие поля будет записан null
- _PATCH_ - обновление. Можно обновлять части уже существующего объекта. Он не будет обновлять отсутствующие поля
