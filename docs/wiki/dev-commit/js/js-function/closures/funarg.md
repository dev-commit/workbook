# Фунарг-проблема

## Информация

::: info

- http://dmitrysoshnikov.com/ecmascript/ru-chapter-6-closures/#funarg-problema - Тонкости ECMA-262-3

:::

## Фунарг

::: tip Определение

- **Фунарг** - сокращение от «функциональный аргумент»

:::

- В _стековых_ языках программирования, локальные переменные функции хранятся в стеке, который наполняется новыми элементами при выполнении функции. При выходе из функции, эти переменные удаляются из стека
- _Ограничения_ для использования функций при "возврате из функции" и при "передаче в виде аргумента"

### Решение

- Использование замыканий

## Виды

::: tip Определение

- **Проблема восходящего фунарга** (upward funarg) - возникает при возврате функции из некоторой функции
- **Проблема нисходящего фунарга** (downward funarg) - возникает при передаче функции в качестве параметра некоторой функции

:::

## Проблема #1: Свободные переменные

- Наиболее характерно Фунарг-проблема проявляется при использовании в функции свободных переменных

::: tip Определение

- **Свободная переменная** (Free variable) - переменная, используемая функцией, но не являющаяся ни параметром, ни локальной переменной этой функции

:::

```js
function testFn() {
  const localVar = 10;

  function innerFn(innerParam) {
    console.log(innerParam + localVar);
  }

  return innerFn;
}

const someFn = testFn();
someFn(20); // 30
```

- В данном случае, для функции _innerFn_ свободной переменной является _localVar_
- Если бы в данной системе использовалась стековая реализация для хранения локальных переменных, это означало бы, что по завершении функции _testFn_, все её локальные переменные должны были бы удалиться из стека, что привело бы к ошибке при вызове функции _innerFn_ снаружи посредством _someFn_
- В данном случае, при стековой организации, и сам возврат функции _innerFn_ был бы невозможен, т.к. _innerFn_ так же является локальной функцией для функции _testFn_ и будет удалена по завершению _testFn_

## Проблема #2: Передача функции в качестве аргумента

- Проблема возникает при организации системы с _динамической областью видимости_

```js
const x = 10;

function someFn() {
  console.log(x);
}

someFn(); // 10 - и при статической и при динамической Scope

(function () {
  const x = 20;
  someFn(); // 10 - при статической, 20 - при динамической Scope
})();

// Аналогично, при передаче someFn
// в качестве параметра

(function (funArg) {
  const x = 30;
  funArg(); // 10 - при статической, 30 - при динамической Scope
})(someFn);
```

- При организации системы с динамической областью видимости, разрешение имени переменной осуществляется в пределах динамического (активного) стека переменных (свободная переменная ищется в динамической цепи вызова, а не в статической цепи создания функции), что может привести к неоднозначности
- При этом, даже, если _x_ будет определена (в отличие от предыдущего примера, где локальные переменные удалились бы из стека и были бы не определены), возникнет вопрос, какое из значений _x_ (точнее, _x_ из какого контекста, какой области видимости) должно использоваться в различных вызовах функции _someFn_?
