## Сравнение Npm, Pnpm, Yarn, Bun

## Таблица сравнения

> У всех четырёх есть **workspaces** для монорепо; в таблице — то, чем менеджеры **реально расходятся**.

| Менеджер | Главные отличия                                                                                                                                                                                                                                         | Комментарии                                                                                                                    |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| **npm**  | Идёт **вместе с Node**. Версии фиксирует в `package-lock.json`. Кладёт пакеты в обычный `node_modules`. Иногда можно импортировать пакет, который **не** записан у вас в `package.json` (он «подтянулся» с другим пакетом)                              | Хватает того, что уже есть с Node; не хочется отдельно ставить другой менеджер                                                 |
| **pnpm** | Ставится **отдельно**. Фиксирует версии в `pnpm-lock.yaml`. Пакеты хранит **в одном общем месте** на компьютере и подключает в проект ссылками — **меньше занимает места**. Обычно видны только те пакеты, которые вы **сами** указали в `package.json` | Много проектов на одной машине, монорепо, хочется меньше «случайных» зависимостей                                              |
| **Yarn** | Ставится **отдельно**. Фиксирует версии в `yarn.lock`. **Старая ветка (1.x)** — по сути как npm. **Новая (2+)** часто работает **без привычной папки** `node_modules` (режим PnP) или с ней — как настроите                                             | Новый Yarn — если хотят PnP или единообразие в команде; старый — часто в старых проектах                                       |
| **Bun**  | **Не** входит в Node. Фиксирует версии в `bun.lockb`. Повторные установки обычно **очень быстрые**. Папка `node_modules` похожа на npm; по правилам импорта ближе к **npm**, чем к pnpm                                                                 | Важна скорость установки и запуска скриптов; иногда ещё запускают код через Bun вместо Node (на своём проекте лучше проверить) |
