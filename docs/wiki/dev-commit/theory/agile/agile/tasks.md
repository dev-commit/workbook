# Задачи

## Backlog

::: tip Backlog

- **Backlog** - приоритезированный список задач, куда записываются пожелания заказчика. Создают Scrum Master и Product Owner
  :::

## Уровни задач

1. **Epic** - большая часть функционала которая может быть завершена в рамках разработки (н-р: разработка личного кабинета пользователя). Эпики делятся на Сторисы
2. **Story** - более мелкая часть функционала которая еще не может случить для задач разработки (н-р: кабинет пользователя может состоять из функционала по авторизации, по рассылке уведомлений и т.д.). Сторис отвечает на вопрос "Я как пользователь хочу ... (н-р: иметь возможность делать посты)"
3. **Task** - идут к разработчикам
4. **Sub-Task** - подзадачи, идут к разработчикам

## Жизненный цикл (workflow) задачи

- `OPEN` - PM создал задачу
- `BACKLOG` - Задача без оценки
- `TODO` - Задача назначена на разработчика
- `IN PROGRESS` - Начало работы над задачей
- `BLOCKED` - Блокер для задачи
- `REVIEW` - Завершена, на ревью
- `READY FOR QA` - После ревью и merge в develop
- `IN QA` / `TESTING` - На тестировании
- `REJECTED` - От тестировщика в случае нахождения багов
- `IN DEV` - На DEV-стенде
- `READY FOR STAGE` - Готова к заливке на stage-стенд
- `ON STAGE` - На STAGE-стенде
- `PENDING RELEASE` - Готова к релизу
- `DONE` / `CLOSED` / `RESOLVED` - Закрыта
- `REOPENED` - PM заново открыл задачу
