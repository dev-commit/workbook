# Монорепозиторий

::: tip Определение

- **Монорепозиторий** - архитектурная концепция, при котрой код множества подпроектов хранится в одном и том же репозитории
- Вместо управления несколькими репозиториями вы храните все изолированные части кода внутри одного репозитория
- «Изолированный» - означает, что архитектура монорепозитория не имеет ничего общего с монолитными приложениями
- Можно хранить много видов логических приложений внутри одного репозитория, например: веб-сайт и его приложение iOS
  :::

**Обычно внутри монорепы:**

- Несколько приложений и/или библиотек с общими зависимостями и явными связями между ними
- Единые правила, CI, линтинг, версионирование (или согласованная схема версий)
- Изменения в нескольких частях системы делаются одним коммитом/PR, что упрощает согласованные рефакторинги

## Инструменты для монорепозиториев

### NX

- https://nx.dev/
- Система сборки, оптимизированная для монорепозиториев, с архитектурным пониманием на основе ИИ и расширенными возможностями CI

### Turborepo

- https://turborepo.dev/
- Бытрый и простой *task runner*
- Описываете pipeline (`build` зависит от `^build` и т.д.), Turbo параллелит задачи и пропускает уже выполненные при неизменных входах
- **Экосистема:** тесно связан с Vercel (Remote Cache удобно подключать к Vercel). Часто используют вместе с *pnpm workspaces* или npm/yarn workspaces без тяжёлого «фреймворка монорепы»

### Lage

- https://microsoft.github.io/lage/
- Оркестратор задач для JS/TS-монорепозиториев: строит граф зависимостей между пакетами, запускает скрипты параллельно и с кэшированием (аналог идеи «pipeline» для `workspaces`).
- Подходит, когда нужно ускорить CI и локальные сборки без смены менеджера пакетов — конфигурация через `lage.config.js` и привычные `package.json` scripts.
