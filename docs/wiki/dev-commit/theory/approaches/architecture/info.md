# Информация

## Информация

### Цель архитектуры

Архитектура frontend-приложения должна обеспечивать:

- предсказуемое развитие продукта по фичам;
- низкую связанность между модулями;
- контролируемые side effects;
- простое тестирование на уровне бизнес-логики и UI;
- возможность параллельной работы команды без конфликтов в коде.

### Базовые принципы

- Разделяйте приложение по бизнес-доменам, а не по типам файлов.
- Отделяйте бизнес-логику от визуального слоя.
- Изолируйте доступ к API/хранилищам в отдельный слой данных.
- Все междоменные сценарии выносите в orchestration-слой.
- Храните composition root в одном месте и собирайте зависимости централизованно.
- Держите роутинг тонким: роут должен выбирать экран, а не содержать бизнес-логику.
- Делайте состояние явным: локальное состояние экрана не должно «утекать» в глобальные модули без причины.

### Результат архитектуры

- Фичи развиваются изолированно и предсказуемо.
- Сценарии с несколькими доменами остаются управляемыми.
- Тестирование становится дешевле и стабильнее.
- Онбординг новых разработчиков ускоряется за счет понятной структуры.
