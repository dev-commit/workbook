# Quality gates: git hooks и правила коммитов

**Quality gates** — набор автоматических проверок, которые блокируют попадание “плохих” изменений в основную ветку. Часто реализуются как:

- git hooks (pre-commit / pre-push / commit-msg),
- CI‑пайплайны (линтеры, типизация, тесты),
- правила форматирования и стиля коммитов.

## Зачем это нужно

- Поймать ошибки как можно раньше (до пуша/CI).
- Сохранять единый стиль и предсказуемость истории коммитов.
- Защититься от “случайных” регрессий (типизация/тесты/линт).

## Типовые проверки

- Линтер + автоформатирование (быстро, по изменённым файлам).
- TypeScript typecheck (по изменённым пакетам или full-run).
- Unit‑тесты (по затронутым пакетам).
- `commit-msg` политика: Conventional Commits + scope.

## Риски

- Слишком “тяжёлый” pre-commit ломает DX и приводит к обходам.
- Непрозрачные правила (что именно упало и как исправить).

## Практика

- Разделять быстрые проверки (pre-commit) и тяжёлые (pre-push/CI).
- Давать режим “changed”, чтобы проверять только то, что затронуто.

## Простой пример

Локальная “проверка” сообщения коммита на стиль `type(scope): subject`:

```ts
function isConventionalCommit(message: string) {
  // очень упрощённая проверка
  return /^[a-z]+\\([a-z0-9-]+\\): .+/.test(message.trim());
}

console.log(isConventionalCommit('fix(api): handle timeout')); // true
console.log(isConventionalCommit('update stuff')); // false
```

## Сравнение

### 1) “По‑простому” (проверок нет)

```ts
// Любой код уходит в репозиторий без типизации/тестов/линта
// → проблемы всплывают у коллег или в проде
```

### 2) По подходу (gates до пуша/мержа)

```ts
// pre-commit: lint/format (быстро)
// pre-push: typecheck + tests (дольше)
// commit-msg: enforce message pattern
//
// Идея: ловим ошибки максимально рано и автоматически
```
