# Type‑safe программный роутинг

**Type-safe routing** — подход, при котором маршруты и навигация описываются так, чтобы TypeScript мог проверять корректность параметров пути и query на этапе компиляции.

## “Программный” роутинг

Вместо файловой маршрутизации (где маршрут определяется именем файла), маршруты собираются программно:

- маршрут — объект (узел дерева),
- дерево маршрутов строится как композиция,
- модули могут добавлять свои узлы в общее дерево.

## Почему это полезно

- Меньше ошибок с URL: параметры типизированы, ссылки сложно “сломать” незаметно.
- Проще модульность: feature‑модули могут поставлять маршруты как часть своего публичного API.
- Явные точки жизненного цикла навигации (guards/hooks) можно стандартизировать.

## Что обычно входит в такой роутер

- Декларативные ссылки (типобезопасный `<Link>`).
- Императивная навигация (`navigate(...)`).
- Хуки доступа к `params`/`query`.
- Layout/Outlet для вложенных маршрутов.

## Риски

- Порог входа выше, чем у file‑based роутеров.
- Нужна дисциплина в дизайне API маршрутов (параметры, алиасы, совместимость).

## Простой пример

Генерация URL с типизированными параметрами:

```ts
type Route<P extends Record<string, string>> = {
  path: string;
  build: (params: P) => string;
};

const userRoute: Route<{ id: string }> = {
  path: '/users/:id',
  build: ({ id }) => `/users/${encodeURIComponent(id)}`,
};

const url = userRoute.build({ id: '42' });
// const bad = userRoute.build({ }); // TS ошибка: не хватает id
console.log(url);
```

## Сравнение

### 1) “По‑простому” (строки руками)

```ts
function userUrl(id: string) {
  return '/users/' + id; // легко забыть encode или перепутать сегмент
}

console.log(userUrl('42'));
```

### 2) По подходу (типизированный builder)

```ts
const userRoute = {
  build: ({ id }: { id: string }) => `/users/${encodeURIComponent(id)}`,
};

// userRoute.build({}) // TS ошибка
console.log(userRoute.build({ id: '42' }));
```
