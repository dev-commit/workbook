## Сложность алгоритма

::: tip Big-O Notation

- **Big-O Notation** - временная сложность алгоритма
- Показывает _верхнюю границу сложности алгоритма_ зависимости между _входными параметрами_ функции и _количеством операций_, которые выполнит процессор
- Нельзя оценивать работу алгоритм с точки зрения времени. Один и тот же алгоритм на разных машинах будет выполняться разное время. Алгоритм включает в себя число шагов. Идея Big-O - сколько шагов нужно сделать чтобы алгоритм завершил свое выполнение
- Показывает работу по _худшему случаю_

:::

::: tip Сложность алгоритма

- **Сложность алгоритма** (вычислительная сложность) - функция зависимости объёма работы, которая выполняется некоторым алгоритмом, от размера входных данных
- Объём работы обычно измеряется временем и вычислительными ресурсами. Время определяется количеством элементарных шагов, необходимых для решения задачи. Ресурсы определяются объёмом памяти или места на носителе данных
- Сложность алгоритма - насколько быстро растет кол-во операций в зависимости от входных данных
- O(n), где n - кол-во входных данных

  :::

## Time Complexity и Space Complexity

::: tip Time Complexity

- **Time Complexity** (Временная сложность вычисления) - сколько нужно тиков процессору, чтобы исполнить операции (максимальное кол-во токов, которое подвязано на входные данные, которые участвуют в алгоритмах). Смотрим какой массив значений приходит на вход - он влияет на Time Complexity

:::

::: tip Space Complexity

- **Space Complexity** (Пространсвенная сложность вычисления) - вся выделенная память, которая участвуют в алгоритме. Н-р: для уменьшение показателей не нужно создавать новый массив, нужно корректировать существующий

:::

## Верхняя граница (отбрасывание констант)

```bash
O(N + N) == O(N)
O(N + 1) == O(N)
O(2N)    == O(N)
```

- Мы говорим как будет вести себя алгоритм на бесконечности
- Если алгоритм для n-элементов выполняет n-тактов плюс один такт для вывода информацим на экран, то сложность такого алгоритма всё равно O(N), т.к. бесконечность гораздо больше единицы. Тоже самое касается алгоритмов, которые выполняются за O(2N) или более
- Big-O описывает только скорость роста. Поэтому мы отбрасываем константы при оценке сложности
- Алгоритм, описываемый как O(2N) должен описываться как O(N)

## Алгоритм

::: tip Алгоритм

- **Алгоритм** - некоторая последовательность действий, которые необходимо совершить для достижения нужного результата
  :::

- Книга: Grokking Algorithms

### Критерии алгоритмов

1. Скорость работы
2. Память (алгоритм должен использовать разумную дополнительную память)
3. Скорость разработки

### 4 асимптотических нотации

4. О-большое - говорит о том, что один алгоритм, «не хуже» другого
5. Омега-большое - говорит о том, что один алгоритм, «не лучше» другого (обратно О-большому)
6. Тета-большое - «алгоритмы примерно одинаковы»
7. о-малое
