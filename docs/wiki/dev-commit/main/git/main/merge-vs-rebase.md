# Merge vs Rebase

## Сравнение Merge и Rebase

| merge | rebase |
| --- | --- |
| История коммитов |  |
| - Есть merge-коммиты, которые указывают сразу на 2 или больше коммитов - Merge не меняет историю: поверх всех коммитов, которые были в ветке, добавляется еще 1 коммит с изменениями из "develop" | - Rebase меняет историю: меняются все хэши коммитов |
| - Сохраняет историю коммитов | - Не сохраняет историю коммитов |
| merge-коммит |  |
| - Добавляется | - Не добавляется |
| Правка конфликтов |  |
| - Один раз | - Для каждого коммита |

## Сравнение истории коммитов для Rebase и Merge

#### Исходные даннные: порядок коммитов

<!-- <img src="../@img/commits-order.jpg" width="250px"/> -->

1. master-0 - master
2. feature-1 - feature
3. master-1 - master
4. feature-2 - feature
5. master-2 - master

#### История коммитов для Rebase и Merge

- merge (слияние) - хронологический порядок
- rebase (перемещение) - у новых коммитов изменится хэш и они будут поверх старых
