# Перенос страниц

Перенос страниц из старого справочника (dev-commit) в новый. Страницы сконвертированы автоматически, разметка правится вручную по правилам ниже. Документ пополняется по ходу переноса.

Пример перенесённой страницы: `docs/wiki/dev-commit/js/js/typing/symbol.md`

## Где что лежит

- Старый справочник: `/Users/tony/Desktop/Repo/@app-workbook/dev-commit/@themes/<тема>/<путь>.html`
- Новый справочник: `docs/wiki/dev-commit/<раздел>/<тема>/<путь>.md`
- Старая страница в браузере: `http://127.0.0.1:1001/pages/<тема>.html#<тема>/<путь>` (н-р, `#js/typing/symbol`)
- Новая страница в браузере: `http://localhost:5173/workbook/<раздел>/<тема>/<путь>` - без `wiki/dev-commit/` и `.html` (н-р, `/workbook/js/js/typing/symbol`)
- Образцы разметки: темы, у которых в `build-*.ts` значение `theme` не равно `"actual"` (`"actual"` - черновик)
- Гайд по разметке: `docs/wiki/dev-commit/system/ui-kit/cases/`
- Старые версии уже перенесённых тем удалены из dev-commit, но есть в его git-истории (`git log --diff-filter=D`)

## Структура страницы

- `# Название` → `## Информация` (определение) → разделы `##` (Использование, Методы, Примеры …) → подразделы `###`
- Заголовки: `<h2>` → `#`, `<h3>` → `##`, `<h4>` → `###`. Уровни не пропускаются: `<h5>` сразу под `<h3>` → `###`
- Вводный раздел с определениями и ссылками («Основное», «Теория») → `## Информация`
- Если вводной части нет (сразу код или разделы) - `## Информация` не добавляется
- Вводный список без заголовка перед кодом → `## Информация`. Код, который сразу поясняет определение, остаётся в ней; самостоятельный пример - в своём разделе (`## Пример`, `## Использование`)
- Страница команды (`<v-method before="git " method="log">`): `` # `git log` `` → `## Информация` с `::: danger` → `## Использование` с кодом и списком после него → разделы из `<h3>`. Образец: `docs/wiki/dev-commit/common/git/command/log.md`
- Подпись в `<b>` внутри пункта списка (`<li><b>Задача:</b></li>`) → `**Задача**` над списком
- Таблица со строками-группами (`colspan`) → группы в первой колонке, жирным
- Подпись над списком (`<b>` в старом) → подзаголовок `###`. `**Жирный**` - для коротких подписей внутри раздела (н-р, «Использовать» / «Не использовать») и внутри раздела `###`
- `<hr>` между самостоятельными блоками → подзаголовок `###` с названием блока (н-р, «Алгоритм»). Если названия не подобрать - `---`
- Комментарии `<!-- TODO: <f-search>…</f-search> -->`, разделители `<!-- xxx -->` и комментарии с именами людей (`<!-- Фамилия -->`) не переносятся

### Определение

```md
## Информация

::: tip Определение

- **Символ** - неизменяемый тип данных, …

:::
```

- Несколько `<u-text-define>` подряд - в одном `::: tip Определение`
- Определение, которое относится к своему разделу (после `<hr>` или внутри `<h3>`), - `::: tip Определение` в этом разделе, а не в «Информации»
- Список, где `<u-text-define>` - только часть пунктов (н-р, «Стандартные HTML страницы», **SPA**, **PWA**), остаётся обычным списком: термины - **жирным**, без `::: tip`
- Страница из одного списка без заголовка - список в `## Информация`

### Описание метода

- Описание после сигнатуры начинается со строчной буквы: `- Получает по …` → `- получает по …`
- Описание аргументов - тоже со строчной, кроме аббревиатур (URL, DOM, HTTP)
- Возвращаемое значение - последним пунктом после аргументов: `> - _return_ - …`. Пустой `<v-method-return>` не переносится
- Аргументы колбэка (в старом - строки через `<br>` внутри `<v-method-arg>`) - вложенным списком

```md
> - `callback` - функция, создающая элемент в новом массиве, принимает три аргумента:
>   - `currentValue` - текущий обрабатываемый элемент массива
>   - `index` - индекс текущего обрабатываемого элемента в массиве
> - `thisArg` - необязательный параметр. Значение, используемое в качестве this при вызове функции callback
> - _return_ - новый массив, где каждый элемент является результатом callback функции
```

**Без return**

```md
::: danger

**`Symbol.keyFor(sym)`** - получает по разделяемому символу его ключ из глобального реестра символов

> - `sym` - разделяемый символ

:::
```

**С return**

```md
::: danger

**`constructor(props)`** - пример описания метода

> - `props` - props
> - _return_ - null

:::
```

### Две колонки

- `<v-two-code comment="A;B">` → `<v-two :title="['A', 'B']">` с блоками кода внутри. Без подписей (`comment=";"`) - обычно один общий блок кода
- `<v-two>` → `<v-two>` с тем же содержимым в `<template #first>` / `<template #last>`
- `<v-two-fix>` → `<v-two fix-right>`: правая колонка фиксированной ширины 200px, левая занимает оставшееся место. Картинка в правой колонке - `style="width: 100%"`. Если в правой колонке что-то шире 200px (н-р, большая схема), то обычный `<v-two>`
- Пропы фиксированной колонки: `fix-left` (левая колонка 200px) и `fix-right` (правая колонка 200px)
- Колонка только с текстом (абзацы, списки) получает отступы как у блоков кода: `text` - текст в обеих колонках, `text-left` / `text-right` - текст только в одной колонке. Колонку, где текст вперемешку с кодом или картинкой, не трогаем
- Теги `<template>` / `</template>` и содержимое - без отступа, вокруг содержимого пустые строки. Если `</template>` с отступом стоит после списка, он попадает в последний пункт списка и страница не компилируется

````md
<v-two :title="['promise', 'async']">
<template #first>

```js
fetch(url).then((res) => res.json());
```

</template>
<template #last>

```js
const res = await fetch(url);
```

</template>
</v-two>
````

### Дерево файлов

- Содержимое `<v-tree>` переносится в блок кода ` ```bash ` и рисуется как дерево: `├──`, `└──`, `│`
- Вложенность в старом справочнике задана табами и пробелами вперемешку - уровень определяется по смыслу (что в какой папке)
- Папки - с `📂`, файлы - без маркера (`›` не переносится)
- Комментарии `# …` - после имени, выровнены по одной колонке
- HTML-теги внутри (`<b>`, `<s>`, `<u-code-mod>` и т.д.) убираются, остаётся текст

**Было**

```text
<v-tree>
📂 <u-code-mod>cypress</u-code-mod>
	📂 <b>e2e</b>
		› <s>test.cy.ts</s>
    📂 <b>snapshot</b>
		📂 <b>actual</b> # Текущей скриншот экрана
		📂 <b>base</b>   # Изображение для сверки
	📂 <b>support</b>
		› <s>e2e.ts</s>
    › <s>tsconfig.json</s>
</v-tree>
```

**Стало**

```bash
📂 cypress
├── 📂 e2e
│   └── test.cy.ts
├── 📂 snapshot
│   ├── 📂 actual  # Текущий скриншот экрана
│   └── 📂 base    # Изображение для сверки
├── 📂 support
│   └── e2e.ts
└── tsconfig.json
```

### Вкладки с кодом

- `<v-tabs>` → `::: code-group`, каждая вкладка - блок кода с подписью в квадратных скобках после языка
- `<v-path>` внутри вкладки становится подписью (путь полнее имени из `:tabs`: `pages/dashboard/index.jsx` вместо `index.jsx`) и больше никуда не переносится
- Образец: `docs/wiki/dev-commit/framework-react/next-js/settings/env.md`

````md
::: code-group

```js [next.config.js]
module.exports = {};
```

```bash [.env]
API_URL=https://jsonplaceholder.typicode.com/
```

:::
````

### Подсветка строк

- Фрагмент в `<u-code-wrapper>` → номера строк в фигурных скобках после языка: ` ```tsx{12,27-36,47-50} `, во вкладке - ` ```tsx{5-7} [App.tsx] `
- Prettier не форматирует блок с `{…}` после языка. Порядок: блок без `{…}` → Prettier → номера строк по отформатированному коду → дописать `{…}`
- Пустые строки на краях выделенного фрагмента не подсвечиваются
- Образец: `docs/wiki/dev-commit/framework-react/react-flow/dagre/use.md`

## Код

- Комментарии начинаются с заглавной буквы: `// встроенные символы` → `// Встроенные символы`. Это касается и комментариев в конце строки
- Продолжение предложения на следующей строке остаётся со строчной. Если на следующей строке новое предложение - оно с заглавной, а предыдущее заканчивается точкой
- Если комментарий начинается с кода (имя, ключевое слово, значение) - регистр не меняется: `// call`, `// this указывает на person`, `// => "Hi Tony"`
- Соседние блоки кода на одну тему объединяются в один
- Заголовок блока кода (`<v-code title="…">`) → комментарий в первой строке: `// Заголовок`. Если он повторяет заголовок раздела над кодом - не переносится
- HTML-сущности в коде (`&lt;`, `&gt;`, `&amp;`) заменяются символами
- Вывод тестовых данных через `alert(…)` заменяется на `console.log(…)`. `alert` остаётся, если пример именно про него (модальное окно, строка кода в `eval` и т.п.)
- Если Prettier меняет смысл примера (убирает значимые скобки, превращает `'use strict'` в середине блока в выражение, дописывает `;` к сигнатуре `Partial<Type>`, разбивает по строкам псевдокод с `'a' | 'b'` внутри объекта), перед блоком кода ставится `<!-- prettier-ignore -->`
- Подчёркнутое `<u>` внутри кода, которое несёт смысл (н-р, выбранный ответ в диалоге `create-next-app`: `No / <u>Yes</u>`), передаётся текстом: остаётся только выбранный вариант (`... Yes`)
- `lang="html"`, где на деле JSX (`className`, `{…}`) → ` ```jsx `
- Язык блока в теме TypeScript - ` ```ts `, код с JSX - ` ```tsx `. Код с `<T,>` - в ` ```tsx `: в ` ```ts ` Prettier убирает запятую, и пример теряет смысл
- Комментарии в bash, выровненные по одной колонке, остаются выровненными
- Синтаксическая ошибка, из-за которой Prettier не форматирует блок, исправляется с сохранением смысла: `return ...;` → `return <div>...</div>;`. Пример, который показывает ошибку, не трогается
- Декоративный `›` перед строками кода не переносится
- Отступ в коде - 2 пробела, в том числе в языках, которые Prettier не форматирует (` ```php `, ` ```sql `, ` ```bash `). Такой код форматируется вручную: табы → 2 пробела, комментарии - по правилам выше, выравнивание комментариев сохраняется
- PHP: пробел после `if` / `for` / `foreach` / `while` / `switch` и вокруг операторов (в том числе `.`), `} else {` на одной строке, `case …:` с двоеточием, код внутри `<?php … ?>` без дополнительного отступа. Образец: `docs/wiki/dev-commit/backend/php/samples/files.md`
- SQL-запросы, которые стояли в блоке другого языка, → ` ```sql `, комментарии `--`
- Блок кода, который на деле перечень функций с комментариями (`empty($a); // пустая ли переменная`), → список: ``- `empty($a)` - пустая ли переменная``. Образец: `docs/wiki/dev-commit/backend/php/other/function-php.md`
- Пароли, токены и логины, похожие на настоящие, заменяются заглушками (`'user'`, `'password'`)

```js
// Задание необязательного аргумента, в котором указывается имя для символа.
// Имя можно использовать для описания символа (полезно для отладки)

// Symbol.iterator используется конструкцией for...of
// благодаря которой можно перебирать (итерировать) объект
```

## Текст

- Опечатки исправляются при переносе
- Строчная буква в начале описания - только в `::: danger`. В остальных списках регистр как в оригинале
- Явные ошибки содержания (неверная команда или описание, текст, скопированный с другой страницы, код, который не запустится) исправляются и перечисляются в отчёте о переносе. Спорные места остаются как у автора
- Устаревшее API (пакет переименован, опция удалена, Pages Router вместо App Router) - текст автора не переписывается, рядом ставится `::: warning` с актуальным вариантом. Подробно - на странице установки, на остальных страницах темы - коротко
- Внутри `::: warning` - список (`- …`). Абзацем - только дословный текст, н-р сообщение об ошибке сборки
- `<u>` / `<em>` с угловыми скобками внутри (`foo<IBasic>`) → `` `код` ``: в `_…_` текст `<IBasic>` разбирается как HTML-тег, и страница не компилируется

## Картинки

- В старом справочнике картинки лежат в `dev-commit/@img/<папка>/`
- Копируются в папку `@img` темы (н-р, `docs/wiki/dev-commit/js/js-promise/@img/`)
- Подключаются путём относительно md-файла: `<img src="../@img/promise-state.png" />`, при необходимости с шириной `style="width: 550px"`
- Внутри `@img` темы картинки лежат в подпапке с именем страницы: `js/js/data-structures/set.md` → `js/js/@img/set/set1.png` → `<img src="../@img/set/set1.png" />`
- Размеры (`width`, `height`) переносятся в `style`, класс `center` не переносится, класс `img200` → `style="width: 200px"`
- Картинка, на которой таблица, заменяется markdown-таблицей (код в ячейках - в обратных кавычках), файл картинки удаляется
- Картинки с одинаковыми именами из разных папок (`config-format/01.png`, `config-format-onsave/01.png`) переименовываются по смыслу: `format-document.png`, `format-on-save.png`
